# Design Document: JobHunter Unified Engine, Frontend, Extension & Desktop Architecture

**Date:** 2026-11-05  
**Status:** Approved & Ready for Planning  
**Target Architecture:** Dual-Mode Engine (MCP Server + REST HTTP Daemon + Clean 5-Tab Dashboard + ATS Autofill Extension + Desktop Runner)

---

## 1. Intent and Why

JobHunter provides an autonomous AI job search and application engine. The latest engine introduces a team of specialists (Scout, Analyst, Writer, Coach, Ops, Reviewer) orchestrated by a CEO MCP tool interface with strict truth-verification and local privacy in SQLite.

To deliver a complete 100% end-to-end user experience, the system provides:
1. A **Web Dashboard** (`public/`) to visualize jobs, compare resumes, see gap reports, track interview prep, and manage application funnels.
2. An **ATS Browser Extension** (`extension/` for Chrome, Edge, Brave) to detect job applications on ATS platforms (Greenhouse, Lever, Workday, Ashby, BambooHR, etc.), autofill candidate facts in one click, solve custom screening questions, and record submitted applications back to the tracker.
3. A **Desktop Launcher** (`desktop.py`) on Windows that runs the local services and automatically launches Chromium with the autofill extension loaded.
4. An **MCP Server** (`mcp_server.py`) for IDEs and AI coding agents (Claude Desktop, Cursor, Antigravity) communicating via standard MCP protocol over stdio without interference or protocol corruption.

This design unifies all components into a coherent, 100% functional system without modifying or destabilizing the newly added engine code and protected LinkedIn scrapers.

---

## 2. Goals, Non-Goals, and Anti-Goals

### Goals
- **Full Interoperability**: Web Dashboard, ATS Autofill Extension, Desktop runner, and MCP Server operate on the exact same SQLite database (`engine.db`), workspace profiles, and `OutputStore`.
- **Zero MCP Protocol Pollution**: Keep MCP stdio strictly clean (logging strictly to stderr; no HTTP traffic on stdio).
- **Unified REST API (`jh/httpd.py`)**: Provide clean REST endpoints for:
  - **Extension**: `/api/extension/status`, `/api/extension/payload`, `/api/extension/solve`, `/api/extension/confirm-applied`.
  - **Profiles & Resumes**: `/api/profiles`, `/api/profile`, `/api/parse-resume`, `/api/profile/activate`.
  - **Jobs & Search**: `/api/search`, `/api/jobs/query`, `/api/recommendations`, `/api/job-details`.
  - **Tools & Generation**: `/api/gap-report`, `/api/cover-letter`, `/api/interview-prep`, `/api/ats-audit`.
  - **Application Tracker**: `/api/applications` (GET to list, POST to upsert/update status, notes, follow-ups).
  - **Desktop**: `/api/desktop/extension-status`, `/api/desktop/launch-browser-extension`, `/api/desktop/open-extension-folder`.
- **Streamlined Modern Dashboard**: Deliver a clean, responsive, dark-mode 5-tab SPA built specifically for the new engine contracts.
- **Reviewer QA Enforcement**: Every document and screening answer generated by the HTTP daemon passes through Reviewer QA (`jh.team.qa.verify_document`).
- **Standard Result Envelopes**: All API responses use the standard `jh.mcp_helpers.envelope` format (`{"status": "ok", "success": true, "data": {...}, "warnings": [...]}`).
- **100% Test Green**: Resolve the single dict-slicing bug in `jh/screening.py` and align test imports so `python -m pytest tests -q` runs 100% green offline.

### Non-Goals
- Changing the protected LinkedIn scraping logic, geo-map, or radar configuration (guarded by `tests/test_protected_linkedin.py`).
- Resurrecting the deprecated 29,000-line legacy monolithic frontend with obsolete endpoints.
- Introducing heavy native GUI packages (`pywebview`, `pystray`) that introduce C-extension compilation and headless CI issues.

### Anti-Goals
- **No stdout pollution**: No HTTP logs or print statements to stdout.
- **No API key leakage**: API keys remain in environment variables only; never returned in API payloads.
- **No unverified output**: Generated applications must always pass through Reviewer QA (`jh.team.qa`).

## 3. Constraints

- **Protected Code**: `LinkedInGuest` and `LINKEDIN_GEO_MAP` in `jh/sources/__init__.py`, LinkedIn radar in `jh/pipeline.py`, and `get_linkedin_scrape_depth`/`get_linkedin_incremental_minutes` in `jh/config.py` MUST NOT be touched (enforced by sha256 hashes in `tests/protected_hashes.json`).
- **Zero External Dependencies**: Server, desktop launcher, and extension installer use Python standard library only (`http.server`, `subprocess`, `urllib`, `winreg`, `os`, `sys`).
- **Offline Test Suite**: `python -m pytest tests -q` must run offline with no external network calls.
- **Manifest V3**: Browser extension complies with Chrome Manifest V3 specifications.

## 4. Architectural Approaches & Builder Decisions

### Approach: Dual-Mode Engine (Dedicated HTTP Daemon + MCP Server)
- `mcp_server.py` handles MCP stdio protocol for IDEs and coding agents.
- `jh/httpd.py` serves local HTTP requests on `127.0.0.1:8765` for the web dashboard and extension.
- Both share the same underlying Python engine modules (`jh.tracker`, `jh.screening`, `OutputStore`, `jh.team`).
- `desktop.py` launches `jh/httpd.py` and provides automated Chromium browser launching with `--load-extension`.

### Explicit Builder Decisions Made:
1. **Dashboard Scope (Clean 5-Tab SPA)**: Build a clean, modular, modern SPA (`public/index.html`, `public/app.js`, `public/styles.css`) tailored specifically to the 5 tabs and REST API. This avoids thousands of lines of dead legacy code while delivering a snappy, bug-free UI.
2. **Desktop Launcher Form Factor (Zero-Dependency Launcher)**: `desktop.py` starts the background `ThreadingHTTPServer` and uses standard library `winreg` / `subprocess` to launch the user's installed browser (Edge, Chrome, or Brave) with `--load-extension`. It includes a system tray / console runner without external GUI packages, ensuring zero installation friction.
3. **Reviewer QA Wrapping**: `/api/cover-letter`, `/api/extension/solve`, and other document endpoints invoke low-level generators and immediately validate drafts using `jh.team.qa.verify_document()`. If ungrounded claims are found, the Reviewer's sanitized output (`rev.adjusted`) is returned with warning badges, ensuring the user is never exposed to hallucinations.
4. **Application Tracker API**: `jh/httpd.py` exposes `/api/applications` bridging directly to `jh.tracker.list_applications()` and `jh.tracker.upsert_application()`. Supported statuses: `saved`, `applied`, `interview`, `offer`, `rejected`.
5. **Response Envelope Standardization**: Every REST response wraps data in `jh.mcp_helpers.envelope`, so both frontend and extension code unpack `res.data`, ensuring uniform error handling, warning tracking, and schema consistency across MCP and REST.

## 5. Detailed Component Specifications

### 5.1 HTTP Daemon (`jh/httpd.py`)
- Python standard-library `http.server.ThreadingHTTPServer` running on `127.0.0.1:8765`.
- CORS headers for `chrome-extension://*`, `http://localhost:*`, and `http://127.0.0.1:*`.
- Static asset serving from `public/` with MIME type mapping (`.html`, `.js`, `.css`, `.png`, `.svg`).
- Endpoints:
  - `GET /api/extension/status`: Health check, active profile name, detected ATS status.
  - `POST /api/extension/payload`: Returns candidate profile, autofill fields, and resume file path for the active profile.
  - `POST /api/extension/solve`: Solves screening questions using `jh.screening.solve_screening_question`, passed through `jh.team.qa.verify_document`.
  - `POST /api/extension/confirm-applied`: Stores application in SQLite via `jh.tracker.upsert_application`.
  - `GET /api/profiles`: Lists available candidate resume variants from `ResumeRegistry`.
  - `POST /api/profile/activate`: Sets active profile variant.
  - `GET /api/applications`: Lists applications from `jh.tracker.list_applications()`.
  - `POST /api/applications`: Updates or creates an application record.
  - `GET /api/search`: Runs job search via `jh.pipeline.search_jobs`.
  - `POST /api/desktop/launch-browser-extension`: Spawns browser with extension via `jh.extension_installer`.
  - `GET /api/desktop/extension-status`: Detects installed browsers and extension folder availability.

### 5.2 Browser Extension (`extension/`)
- **`manifest.json` (Manifest V3)**:
  - Name: "JobHunter Copilot & ATS Autofill"
  - Permissions: `["activeTab", "scripting", "storage"]`
  - Host permissions: `["http://127.0.0.1:8765/*", "<all_urls>"]`
  - Content scripts on `<all_urls>`: `content.js` and `flyout.css`.
  - Background service worker: `background.js`.
  - Action popup: `popup.html` and `popup.js`.
- **`content.js`**:
  - Detects ATS patterns (Greenhouse, Lever, Workday, Ashby, BambooHR, SmartRecruiters, Jobvite, generic job forms).
  - Renders floating "⚡ JobHunter Copilot" badge in the bottom-right corner.
  - 1-Click Autofill: Populates First Name, Last Name, Email, Phone, LinkedIn, GitHub, Website, Location, and Years of Experience.
  - Inline Screening Solver: Highlights questions and solves them on click using verified candidate facts.
  - Auto-tracks on form submit: Sends submission event to `/api/extension/confirm-applied`.

### 5.3 Web Dashboard (`public/`)
- Modern dark-mode SPA (`index.html`, `app.js`, `styles.css`) using responsive flexbox/grid.
- Tabs:
  1. **Radar / Job Search**: Live search queries, filter by location, remote, match score; view compact job cards with match skills and gap breakdown.
  2. **Profiles & Resumes**: Manage candidate profiles, view parsed skills, switch active resume variant.
  3. **Application Kanban Tracker**: Columns for `Saved`, `Applied`, `Interview`, `Offer`, `Rejected` with drag-and-drop or status-select updates, notes, and follow-up alerts.
  4. **Document Studio**: Review tailored resumes, cover letters, and interview prep guides.
  5. **Extension & Desktop Hub**: Browser extension status badge, 1-click browser launcher, and manual extension load instructions.

### 5.4 Extension Installer & Desktop Runner (`jh/extension_installer.py`, `desktop.py`)
- Detects Chrome, Edge, and Brave executables via Windows Registry (`SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths`).
- Resolves absolute path to `extension/` directory.
- Spawns browser with `--load-extension="<path>"` pointing to `http://127.0.0.1:8765`.
- Copies extension path to clipboard as a fallback for manual loading in `chrome://extensions`.

### 5.5 Test Suite Alignment & Bug Fix
- **Bug Fix in `jh/screening.py`**:
  - In line 231, change:
    ```python
    "required_skills": job.get("required_skills", [])[:8],
    ```
    to safely handle dictionaries:
    ```python
    "required_skills": list(job.get("required_skills", {}).keys() if isinstance(job.get("required_skills"), dict) else job.get("required_skills", []))[:8],
    ```
  - This immediately turns the 3 failing tests (`test_apply_flow_reviews_every_document_and_saves_approved_files`, `test_what_the_writer_produces_for_real_jobs_passes_the_reviewer`, `test_prepare_application_bundles_and_tracks`) green!
- **Legacy Test Harmonization**:
  - Update legacy tests (`tests/integration/test_mcp_tools_catalog.py`, `tests/security/test_security_policies.py`, `tests/test_filestore.py`, `tests/unit/test_dedup_and_scoring.py`, `tests/unit/test_schemas_and_envelope.py`) to import `OutputStore` and `jh.mcp_helpers.envelope` instead of deprecated classes, ensuring the full pytest suite is 100% green.
